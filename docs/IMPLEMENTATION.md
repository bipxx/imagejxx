## Native dataset foundation

The public C++ API in `include/imagejxx/dataset.hpp` now provides explicit time, scientific channel, Z, Y, X and RGB/RGBA sample axes; immutable plane and region sources; independent plane replacement with shared unchanged storage; and spacing/origin/direction/time calibration. The source interface supports lazy implementations without requiring eager pixel reads during metadata inspection. XZ/YZ extraction requests bounded rows or columns, allowing tiled sources to avoid full XY materialization. Existing `Image`, `Stack` and Python array APIs retain their meanings.

`SharedPlanes` supplies the same immutable eager buffers to headless datasets and desktop documents. Worker snapshots, history, duplicate documents and substacks share unchanged buffers. A local edit replaces its affected plane; metadata history does not allocate pixels. Pruning history releases obsolete planes when no reader still owns them. Legacy stack kernels and writers still use explicit full materialization; typed/virtual desktop sources and bounded caches remain required.

Python exposes the same types:

```python
import numpy as np
import imagejxx as ij

pixels = np.arange(2 * 2 * 3 * 4 * 5, dtype=np.uint16).reshape(2, 2, 3, 4, 5)
cal = ij.SpatialCalibration(spacing=(0.5, 2, 3), origin=(10, 20, 30), unit="um")
dataset = ij.Dataset(pixels, axes="TCZYX", calibration=cal)
xz = dataset.plane("xz", 2, t=1, c=1)  # horizontal X, vertical Z, fixed Y=2
region = dataset.region(1, 1, 3, 2, t=1, c=1, z=2)
geometry = dataset.plane_geometry("xz", 2)
changed = dataset.with_plane(np.zeros((4, 5), np.uint16), t=1, c=1, z=2)
original = dataset.numpy("TCZYX")  # explicit full materialization
```

`C` denotes scientific channels. `S` denotes interleaved RGB/RGBA components: `axes="YXC"` and `axes="YXS"` give different interpretations of the same three-dimensional array. Axis labels are required for new datasets. Plane reads return detached arrays; modifying them cannot mutate the dataset. `with_plane` returns a new dataset and leaves its source unchanged.

Integer voxel coordinates locate voxel centers. `origin` is the world position of voxel `(0,0,0)`, and the row-major direction matrix maps spacing-scaled XYZ vectors into world space. This explicit convention still needs adapters for ImageJ origin metadata and every derived-image operation.

```python
from imagejxx.ui.app import Editor
from imagejxx.ui.model import Document

editor = Editor()
editor.add_document(Document(pixels[0, 0], is_stack=True))
live = editor.live_document()
```

## Native editable documents and transactions

The headless API in `include/imagejxx/document.hpp` now owns immutable dataset/metadata/selection/ROI snapshots and mutable staged edits. C++ and Python expose the same `Document`, `DocumentSnapshot` and `DocumentTransaction` contract. Native snapshots retain shared pixel buffers after edits, undo or destruction of their owner; inspecting a lazy dataset or editing its metadata does not read its pixels. Prepared planes share buffers with committed data when the source has not changed.

```python
import imagejxx as ij

document = ij.Document(dataset, title="Experiment")
source = document.snapshot()
edit = source.begin_edit()
edit.replace_plane(source.dataset.plane(coordinate=2, t=1, c=1) + 1, t=1, c=1, z=2)
edit.set_property("comment", "Corrected one plane")
preview = edit.preview()             # owner pixels/history/dirty state unchanged
document.commit(edit)                # one atomic history step
document.undo()

# The optional desktop accepts the same transaction type for an existing Z stack.
edit = live.begin_edit()
edit.set_title("Reviewed")
live.commit(edit)
native_snapshot = live.native_snapshot()  # no JSON pixel serialization
```

Documents have separate monotonically increasing pixel, metadata, selection and display revisions. Default transactions depend on pixels, metadata and selections; zoom/crosshair changes can coexist with processing. Retained owner tokens reject foreign commits even if numeric IDs collide. Failed preparation, stale commits and unsupported desktop replacements leave the document unchanged and the transaction active for inspection or rollback. Successful commit or explicit rollback closes it. No-op edits create no history step; active selection changes alone do not mark data dirty. Stored ROI changes are metadata edits and carry selection revisions.

Callers can explicitly choose narrower revision dependencies, for example `begin_edit(ij.Change.PIXELS)` for an independent metadata patch. Only touched properties and planes merge into the current document; unrelated concurrent patches survive. The caller must include every category its operation reads. Omitting a dependency deliberately permits overwriting that touched field; it does not provide automatic same-field conflict resolution. A transaction is a mutable staging object and must not be used concurrently by multiple threads. Headless document snapshot/commit/history methods serialize their updates; custom lazy sources must support the concurrent reads requested by their callers.

Native metadata supports null, booleans, int64/uint64, finite numbers, strings and recursive arrays/objects. Immutable container nodes retain exact unsigned values and share nested storage; legacy scalar/string-list alternatives remain available to C++ callers. Calibration and optional T/C/Z ROI positions validate against the dataset. Geometry uses the existing rectangle, ellipse, polygon, freehand, line, polyline, angle, point, multipoint and packed-mask rasterization. Full editable geometry, stable ROI identities, specialized style controls, scientific metadata interpretation, operation effects and ImageJ ROI interchange remain in M1/M4/M8.

Desktop adapters retain legacy unknown metadata and ROI extension records, expose categorized revisions in `live.info`, and commit directly to the addressed document while another tab is active. Contrast ranges and LUT changes are display-only: they create no pixel history/dirty state, survive pixel undo/redo and remain usable while a worker prepares a pixel edit. Jobs validate data revisions and keep their original source slice, so later navigation cannot retarget an edit. Typed snapshots can be consumed outside the editor thread; desktop access and commits remain on its creator thread. `live.close(discard=False)` and `editor.close_document(...)` reject unsaved documents unless discard is explicit, and retained native snapshots remain readable after closing.

This adapter accepts eager Z stacks only. It explicitly rejects scientific desktop C/T axes, virtual replacement sources and T/C-positioned ROI records rather than dropping their meaning. Its lossless records do not yet provide scientific-format interpretation or a v3 session schema. Native documents and the desktop share step limits and an obsolete-eager-pixel budget. Shared dataset execution, full byte/resource budgets, kernel cancellation and non-pixel operation registration/recording are still required before M1 closes.

## Headless application controller

The public [application contract](../include/imagejxx/application.hpp) registers
and activates native documents, resolves stable IDs, publishes transactions and
display state, manages history/save identities and closes membership. It has no
GUI, Python or JSON dependency. Python exposes the same `Application` class.
Adopting a `Document` retains its existing owner and immutable data; direct
document edits and controller edits are immediately visible to each other.

```python
import imagejxx as ij
import numpy as np

controller = ij.Application()
owner = ij.Document(ij.Dataset(np.zeros((3, 64, 64), np.uint16), axes="ZYX"))
document_id = controller.adopt(owner)
controller.set_history_policy(8, 1024 * 1024, document_id)
source = controller.snapshot(document_id)
edit = controller.begin_edit(document_id)
edit.replace_plane(np.full((64, 64), 42, np.uint16), z=1)
view = source.display
view.crosshair = [32, 32, 1]
controller.commit(edit, display=view)
saved = controller.snapshot(document_id)
controller.mark_saved(saved)  # after the caller has successfully saved this snapshot
controller.close(document_id)
pixels = saved.dataset.plane(coordinate=1)  # retained after membership closes
```

Zero IDs resolve the active document. Closing an earlier document preserves the
active identity; closing the active one selects a remaining neighbor. Unsaved
close requires explicit discard. Closed IDs cannot be re-adopted by that
controller, and pending edits cannot publish to them. Retained snapshots and
independently owned adopted documents remain usable. Registry/publication
methods serialize access; processing uses snapshots outside the registry lock.

`Document(snapshot)` imports complete metadata, positioned/styled ROIs, overlays,
previous geometry, display and Fourier records into a new clean owner with empty
history. `Application.duplicate()` uses that same import contract. Immutable
dataset and Fourier storage remains shared. `Dataset.shares_pixels()` reports
whether datasets retain the same immutable source. `snapshot.shares_data()` checks retained
document-record identity; display and save-state changes keep that data object.

Native `commit` can publish prepared data and an optional validated display state
atomically. Invalid display state leaves the edit active and the owner unchanged.
`preserve_concurrent_display=True` keeps navigation/display changes made since
the edit's source snapshot. Display-only publication creates no data history.
Committed snapshots carry `data_identity`; previews have none. Marking an older
successfully saved snapshot preserves newer edits as dirty, and foreign or
preview snapshots cannot mark a document saved.

`history()` reports step counts, policy and eager plane-buffer storage. Budgets
count unique obsolete buffers across undo/redo, using the current double-backed
working representation. Figures exclude externally retained snapshots, spectra,
reader caches and processing scratch. Lazy sources report `pixels.exact=False`
without reading pixels; complete lazy/cache/global accounting remains M10 work.

The desktop now registers its native owners with this controller. Importing a
snapshot still creates an independent owner; attaching an existing `Document`
shares the actual owner and its history. Execution over the resolved targets,
shared jobs/resource budgets, geometry policies and v3 sessions remain delivery
3 work.

## Native metadata and retained document records

The headless [metadata contract](../include/imagejxx/metadata.hpp) has no JSON or
GUI dependency. Python uses ordinary detached dictionaries/lists. Nested values
validate before staging: nonfinite numbers, nonstring object keys, integers
outside int64/uint64, cycles and nesting beyond 128 containers are rejected.
Tree equality compares values, so reassigning an equal decoded record creates no
history step. Transactions merge only the extension/property keys they touch.

Small unsigned C++ integers retain their original int64 conversion alongside
full-width uint64 storage. `MetadataValue` provides standard variant access and
traits while resolving those conversions. Equal nonnegative signed/unsigned
integers, and equivalent legacy string lists/recursive string arrays, compare by
value across decoding; booleans remain distinct from integers.

Native snapshots now retain selection/ROI `attributes`, complete overlay records,
previous selection geometry, display `properties`, arbitrary session extensions,
extra calibration fields and nested `native_properties`. Desktop JSON conversion
is a compatibility boundary. Existing records are represented in the native
snapshot rather than skipped because they cannot fit a scalar property. ROI
replacement publishes each complete record, including its attributes; clearing
attributes removes them without guessing identity from duplicate names.

```python
snapshot = live.native_snapshot()
edit = snapshot.begin_edit()
edit.set_property("acquisition", {"series": [0, 1], "id": 2**64 - 1})
edit.set_extension("vendor", {"reviewed": True})
edit.set_overlays(snapshot.overlays)
live.commit(edit)

display = live.native_snapshot().display
display.properties = {"display_range": [0, 100], "lut": "Fire"}
live.set_display(display)            # no pixel history or dirty-state change
```

Display dictionaries are detached; assign the edited dictionary back to
`display.properties` before applying it. The current desktop accepts its existing
range/LUT/custom-LUT properties and rejects unsupported display fields and C/T
positions. Extension writes cannot override canonical desktop fields such as
selection or spatial calibration. Extra calibration records remain available
under `metadata["extensions"]["calibration"]`; `set_calibration` owns the
spatial/time fields.

## Resolved operation targets

The public C++ contract in `include/imagejxx/targets.hpp` and its Python bindings
capture a source snapshot, owner identity, data revisions, explicit T/C/Z ranges
or ordered positions, ROI policy, plane/volume execution and output destination.
`Application.resolve_target()` checks membership; `validate_target()` checks that
the member remains open and its required data revisions still match. Display
navigation does not change the frozen positions or invalidate data work.

```python
import imagejxx as ij
import numpy as np

document = ij.Document(ij.Dataset(np.zeros((2, 3, 5, 4, 6), np.uint16), axes="TCZYX"))
app = ij.Application()
app.adopt(document)
request = ij.TargetRequest(
    ij.TargetScope.RANGES,
    t=ij.AxisRange(0, 2), c=ij.AxisRange(1, 3), z=ij.AxisRange(1, 5, 2),
    roi=ij.RoiPolicy.WHOLE_PLANE,
)
target = app.resolve_target(request, operation="add")
assert target.position_count == 8
record = target.record()
restored = ij.target_from_record(document.snapshot(), record, "add")
app.validate_target(restored)
```

Ranges are half-open `[start, stop)` with a positive step. An omitted stop means
the axis extent; an omitted axis in a range request captures that display index.
Range targets retain three compact ranges even for millions of positions.
Explicit positions preserve input order and reject duplicates. A resolved target
owns its copied request and retained source; later request edits cannot change it.
Invalid bounds, contradictory fields, unknown operations and unsupported volume
methods fail before pixel reads. Volume selections require contiguous Z planes.

`mask(index)` returns the frozen active selection, a union of saved ROIs matching
the position's optional T/C/Z fields, or `None` for whole-plane application.
Unmatched positioned ROIs produce an empty mask. Holes and disconnected regions
retain their raster coverage. Mask rasterization does not read source pixels.
Whole-plane targets depend on pixels/metadata; selection-dependent targets also
depend on selection revisions. `begin_edit()` uses those dependencies, while
publication still validates revisions and frontend constraints.

Records contain a schema version, source ID/data revisions and TCZYXS shape,
frozen ranges/positions, ROI policy, mode and destination. Native/Python JSON
round trips preserve exact IDs and support compatibility empty-list metadata.
Malformed or stale records fail; a record never silently rebinds to another
document or its current slice. Cross-document workflow replay needs an explicit
source-binding adapter in M12.

The eager-Z desktop's existing current-slice/all-slices processing now resolves
the same native targets and masks. `LiveDocument.resolve_target()` exposes the
contract for that live owner without serializing its pixels. Legacy all-slices
means all Z at the captured T/C; an explicit legacy slice index overrides current
Z. The installed [C++ example](../examples/cpp/targets.cpp) uses the target to
prepare selected planes and publish one transaction with one undo step.

This completes the target-resolution contract in delivery 3a, not the full
processing-extent family. Shared plane execution and publication now have the
delivery 3b evidence below. Complete target controls, scientific desktop axes,
jobs/resource budgets, geometry effects and v3 sessions remain assigned to
delivery 3c onward and M5/M6. The
existing 80 registered kernels still support XY planes rather than true volume
neighborhoods.

The public headless contract in `include/imagejxx/execution.hpp` prepares an

```python
import imagejxx as ij
```

Preparation reads only selected planes and leaves the source, dirty state and

count when `return_num=True`; counts are restricted to the selected pixels, and a
skipped position returns zero only when a count was requested. Outputs remain
separate from document records and history. No-op native edits leave history and
dirty state unchanged.

The default `DatasetPolicy.PRESERVE_UNTARGETED` retains a common lossless dtype
for partial conversion: narrowing clips selected values while preserving the
unselected source values, and widening promotes untouched lazy planes on demand.
Whole-dataset conversion honors the requested output dtype. Bulk same-type edits
copy a shared plane table once and share unchanged buffers. Shape/sample changes
require full-plane coverage across the dataset. The explicit legacy desktop
profile retains the existing eager-stack type/mask and geometry behavior.

`GeometryPolicy.REQUIRE_TRANSFORM` rejects spatial transforms until their explicit

and document locks. Cancellation checks run between planes and before

## Shared native jobs

The headless [jobs contract](../include/imagejxx/jobs.hpp) supplies bounded native
workers, FIFO workspace admission, cancellation and retained status/error
snapshots, with separate current-phase and completed-plane counts.
`Application.submit()` freezes the normalized parameters and resolved
target before queuing work. Invalid parameters, unsupported geometry/volume
requests and oversized reservations fail before admission or source reads.
Native tasks run outside application/document locks; Python waits release the
GIL. Generic C++ tasks are supported by `JobScheduler`; Python schedules native
operations rather than arbitrary Python processing callbacks.

```python
import imagejxx as ij
import numpy as np

app = ij.Application()
owner = ij.Document(ij.Dataset(np.zeros((4, 6), np.uint16), axes="YX"))
app.adopt(owner)
app.job_scheduler.set_limits(ij.JobLimits(workers=2, memory_budget=256 * 1024**2))
job = app.submit("add", app.resolve_target(), {"value": 5})
job.wait()
assert job.info.state == ij.JobState.READY and owner.undo_steps == 0
preview = job.prepared.preview
published = app.publish(job)
assert published.document_id == owner.id and owner.undo_steps == 1
```

The states are Queued, Running, Ready, Publishing, Completed, Failed and Canceled.
Ready means the worker has prepared an isolated result; it has not edited the
document. Publication runs on the caller's permitted thread, validates owner
membership and revisions, preserves permitted display changes and creates one
undo step. Cancellation wins until publication starts; after that transition it
returns false. Failed/stale publication records the original error. Retained
prepared previews remain readable after cancellation, stale failure or close
when a result was produced; they cannot bypass publication validation.

`JobOptions(label=..., supersedes=...)` cancels older work with the same key and
document when a replacement is admitted. Rejected admission leaves the older
job intact. `job.cancel()` and `app.job_scheduler.cancel(job.info.id)` address one
job. Document close and service shutdown cancel affected unpublished work; queue
shutdown joins workers. Status snapshots are detached values. The service prunes
terminal records when its status index exceeds 128 entries, retaining unfinished
work independently of that history threshold.

Queued cancellation releases the task's captured pixels, parameters and reader
owners before the cancel call returns, even when every worker is occupied.
Supersession and document close do the same for affected queued work. Capture
destructors run outside scheduler, job and application locks and can query the
native controller. Shutdown releases queued captures before joining running
workers. Running tasks keep their captures until work exits; retained prepared
previews keep their separate lifetime. Pruned failure objects are also released
outside scheduler locks. A source closed during admission causes the replacement
to be canceled before `Application.submit()` returns.

Both launch modes use the same native queue and **Window > Jobs and log** panel.
It provides recent tasks, source IDs, states, current-phase and plane progress,
workspace requests, task/phase/error filtering, retained diagnostics and per-job
Cancel controls. Running tasks show the current phase's count; plane completion
remains available separately and stage counts restart when the phase changes.
`editor.action("show_jobs")`, `editor.jobs`, `editor.job_info` and
`editor.cancel_job(id)` expose the same state/control from Python. The panel can
be hidden with `editor.action("show_jobs", visible=False)`. `editor.wait()`
consumes and raises the current error; the failed job's diagnostic remains in
`editor.jobs` for inspection. Automatic parameter-driven preview scheduling and
phase coverage for the remaining operation/reader paths remain required.

`JobInfo.stage`, `stage_completed` and `stage_total` retain the last named phase
independently from `completed`/`total` plane counts. C++ callers can observe
`ExecutionControl.stage_progress(name, completed, total)` or report generic job
phases through `JobContext.stage_progress()`. Python reads the same job snapshots.
Borrowed phase names are copied into the job record; invalid generic phase counts
retain a failed-job diagnostic. Callback errors/cancellation abort preparation.

`processing_workers` and `processing_memory_mb` configure the shared service.
Preference-save rejection preserves the previous effective limits. Workspace
reservations currently estimate running-job work; they are **not a whole-process
memory ceiling**. Retained previews, source documents, history, caches and

These estimates follow argument normalization. Exact allocation accounting for

Polling uses a constant-initialized thread-local scope, avoiding MSVC's repeated

## Binary morphology options and preferences

The C++ `binary_morphology` entry point and `BinaryMorphologyOptions` in
`include/imagejxx/binary.hpp` provide eight-neighbor erosion, dilation, opening
and closing of single-sample uint8 images containing only 0/255. Erosion counts
background neighbors, dilation counts foreground neighbors, and the center is
excluded. The inclusive neighbor threshold is 1–8. Opening performs N erosions
followed by N dilations; closing reverses those stages. N is 1–100. Two pixel
buffers are reused across iterations. Validation, erosion and dilation have
named progress phases and cancellation checkpoints; interrupted work leaves
the input and document unchanged.

`Settings.binary_options()` returns a detached native options value from
`binary_iterations`, `binary_neighbors`, `binary_black_background` and
`binary_pad_edges`. Defaults are one iteration, one neighbor, foreground 255
and no edge padding. Padding supplies foreground beyond the image boundary
during erosion, including the erosion stage of closing. Dilation always sees
background outside the image. These are explicit pixel-value rules; display
LUTs do not change them. Existing grayscale morphology and ROI grow/shrink
defaults retain their earlier semantics.

**Process → Binary** exposes four distinct commands with integer fields,
checkboxes, Preview and Apply in the shared C++ ImGui panels. Searchable
preferences, group reset, portable import/export, native/Python reopen and
recording use the same validated settings. Explicit command parameters override
preferences. An opened dialog keeps its draft, and recorded steps retain all
four effective values. Preview and Apply use the existing resolved-target
executor: compute from the full plane, then write the selected region while

## Shared settings and preferences

Auto threshold display now consumes the shared **Threshold** settings group.
Successful Auto calculations save the method, bright/dark and endpoint flags;
opening a panel restores them in both launch modes. Protected preference files
remain untouched. See [threshold settings and limits](THRESHOLDING.md).


`include/imagejxx/settings.hpp` supplies a headless C++ settings schema and atomic validated updates. The Python `imagejxx.Settings` type, native startup, both desktop launch modes and the searchable ImGui **Preferences** panel use that schema. The panel provides group filtering, editable drafts, Apply, Defaults, Revert, Import and Export. Rejected patches leave settings and their file unchanged.

The current settings have consumers: theme, UI/font scale and display DPI; canvas background, initial physical-view zoom (specified in X screen pixels per image pixel) and display interpolation; foreground/background colors, independent brush/line/point sizes and annotation text size; ROI visibility and wand tolerance/connectivity; Z playback rate; undo step/pixel budgets and processing workers/workspace reservations; result column selection and decimal formatting, line-profile sample count; and PDF resolution/orientation. Result selection changes the table and CSV columns, rather than which measurements are computed. Formatting preserves full precision in native results. Display interpolation leaves image pixels unchanged.

```python
import imagejxx as ij
from imagejxx.ui.app import Editor

settings = ij.Settings({"theme": "light", "line_width": 3})
settings.update({"wand_tolerance": 10, "wand_connectivity": 8})
editor = Editor()
editor.update_settings(settings.to_dict(), persist=False)
editor.action("show_preferences", search="wand")
# editor.run() starts the same native ImGui desktop used by the C++ executable.
```

`editor.settings` returns a detached settings value; use `update_settings` to change the live editor. Existing `preferences` actions now patch supplied fields without resetting unrelated values. Preferences use a versioned `imagejxx-preferences` JSON envelope. Legacy flat files, named/short hexadecimal paint colors and the former shared brush/point size migrate through the native schema. Unknown setting, extension and top-level fields survive a round trip. Invalid known fields recover individually with visible warnings; malformed or unsupported files remain untouched on startup. Explicit repair saves preserve the original in a numbered `.bak` file. Native and Python writers replace files through unique same-directory temporary files.

Both launch modes honor `IMAGEJXX_CONFIG_DIR`; otherwise they use the platform configuration directory and retain the legacy home-directory migration path. Preference import is strict, and reset can target one group or all current settings.

The native `wand_mask` kernel and NumPy interface share seed-relative tolerance and four/eight connectivity with the desktop wand. Complete threshold-aware wand modes still belong to M4/M6. Undo budgets count each obsolete shared pixel buffer once per document, exclude current planes, and prune existing history immediately when lowered. This is an undo pixel budget, not a global application memory ceiling: metadata, spectra, workers, textures, caches and storage across documents still need the planned resource controls.

M2 remains in progress. The binary morphology defaults now have native/shared-panel consumers. Conversion defaults, remaining binary output conventions and richer drawing, point/text, measurement/plot and scientific-file options accompany their consumers in M4/M6/M7/M8. Shortcut editing, startup behavior, accessibility and multi-platform/DPI verification remain required. The currently exposed PDF defaults do not yet cover system-print settings. Full orientation controls, derived-view policies and positioned ROI projection/editing remain in M1/M3/M4.
