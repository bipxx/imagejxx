## Ownership boundaries

| Role | Owned responsibility | Handoff and waste review |
| --- | --- | --- |
| Core/API | Native kernel/target/admission/state modules and required Python API bridges. No concurrent Window edits. | Freeze complete source/context/ROI/CZT; agree estimates/results/compatibility. Review copies, validation duplication, API/header rebuild cost and reuse of existing numerical functions. |
| Consumer/UI | Window integration and relevant private panels/controllers for both hosts; settings, replay, persistence and result ownership. | Exactly one Window editor at a time. Reuse existing jobs/caches. Review repeated frame queries, source retention, growing hub responsibilities and duplicated host logic. |
| Validation/integration | Independent references, affected native/Python/actual ImGui/installed SDK checks, CI route, retained evidence and final merge review. | Match checks to change scope; preserve references/tolerances and failed diagnostics. Review redundant runs, harness generation, storage/retention and claimed platform scope. |

Owners define file boundaries before editing. Shared headers and registry changes
are coordinated once, then dependent consumers follow. No worker reverts another
owner's changes. Join handoffs into one coherent integration result; do not keep
three build/environment generations. An independent reviewer is used when
required/authorized or a concrete risk warrants it, not as an automatic ceremony.

## Task completion

Every role uses [the same closeout](PLAN.md#task-closeout-and-waste-review):
state the delivered scope, select relevant checks, review waste, safely retire
owned scratch, assign any deferred improvement and update PLAN in place.
Role success is not full-feature or full-platform completion. A feature may be
implemented/verified while another integration or release aspect remains open.

P1 creation counters/positions and P2a/b native/shared point presentation are
scoped integrated. Both Windows hosts qualify controls/defaults, ordinary and
scientific properties and cached drawing.582 focused product checks pass (one
optional OpenGL skip),40 tools (one platform-link skip), native controls and
seven installed SDK clients per Windows/Linux platform. Next P2c raster flatten/
interchange, then P3 automatic actions and P4 reconciliation. PLAN owns precise
limits and next-two specs. Reuse immutable glyph templates and existing state/
font/export owners; inspect capability/popup/schema boundaries before captures.
All task scratch is retired with verified retention; inaccessible storage remains
unknown. Update scope, waste decisions and the queue after every task.

Follow the [remaining-work sequence](PLAN.md#execution-sequence-to-finish-the-remaining-work).
After each accepted task, update its current queue entry and waste disposition
before the next start; unresolved consumers stay attached to their parent task.
