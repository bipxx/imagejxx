## Desktop use

Open **Image > Stacks > Reslice physical spacing...** on an eager T1/C1 document.
Choose XZ or YZ, inclusive First/Last indices and a positive Step. Desktop indices
are one-based. Select Nearest or Linear and enter positive physical Z spacing in
the source calibration's spatial unit. Spacing applies along source Z **before
transpose**, so its meaning stays the same when output axes are exchanged.

Reverse changes the order of selected planes. Flip reverses the original source
Z extent before sampling. Transpose exchanges the two output axes; it follows
the earlier orientation API's transpose meaning. The native estimate supplies
the preview's grid count, selected endpoints, axes, dimensions and working-byte
estimate. The form uses the processing-memory preference and checks its render
limit before processing. An active GL context supplies its texture limit;
headless controls have a frontend-only 4096 limit. Native headless APIs have
their own checked dimensions and memory admission.

The form retains its captured document and request. Later navigation or tab
changes do not retarget the export. Cancel creates no output. Invalid, busy,
closed, canceled or stale pixel/calibration work fails atomically. Selection or
display changes alone are allowed. Successful publication creates and activates
a fresh document with output calibration and typed export provenance; it clears
selection, previous selection, saved ROIs, overlays, spectrum and other source
annotations/properties. The new document starts with zero undo/redo history and
ordinary `dirty=false` state. Source pixels, annotations and history remain
unchanged.

## Grid and sample rules

Let `Lz` be the Euclidean norm of the source's complete Z world-basis vector,
including direction and nominal spacing. For requested physical spacing `h`,
the voxel step is `delta = h / Lz` and the vertical count is
`M = 1 + floor((Nz - 1) / delta)`, evaluated with the specified binary64
arithmetic and no epsilon. Samples start at the source endpoint's voxel center.
The far endpoint appears when it lies on this grid; an unaligned endpoint is
not appended. Flip starts at the other original endpoint. Output origin,
signed/sheared basis, selected time and units follow this coordinate mapping.

Nearest copies the nearest stored sample. Linear copies exact endpoints and
equal-value branches; it quantizes only newly interpolated values according to
the declared pixel type. Finite stored native doubles are preserved on copy
branches. The reviewed eager grayscale Float32 quiet-NaN policy supports
Nearest and refuses Linear before processing. Unknown lazy providers cannot
admit that quiet-NaN policy. Invalid or unrepresentable grids and the documented
working-memory estimate fail before provider reads or progress callbacks.
This estimate does not certify global renderer caches, provider caches, history
or total process memory; those resource obligations remain assigned.

## Python API

Coordinates and inclusive range endpoints in the core APIs are zero-based.
Scientific T/C selection is available in the headless APIs even though this
desktop increment is limited to T1/C1.

```python
import numpy as np
import imagejxx as ij

pixels = np.arange(5 * 3 * 4, dtype=np.float64).reshape(5, 3, 4)
source = ij.Dataset(
    pixels, axes="ZYX",
    calibration=ij.SpatialCalibration(spacing=(1, 1, 2), unit="um"),
)
orientation = ij.AxisRangeOrientationRequest(
    ij.AxisRangeResliceRequest("xz", 0, 2, 1, t=0, c=0),
    reverse_order=False, flip_vertical=False, transpose=False,
)
request = ij.AxisRangeSpacingRequest(
    orientation, physical_vertical_spacing=1.0,
    sampling=ij.AxisRangeSampling.Linear,
)
estimate = ij.estimate_axis_range_spacing(source, request)  # Metadata only
result = ij.reslice_spaced_axis_range(source, request)
planes = result.dataset.numpy("ZYX")

owner = ij.Document(source, "Volume")
app = ij.Application()
app.adopt(owner)
prepared = app.prepare_axis_range_spacing(request, owner.id)  # Request first
published = app.publish(prepared)
```

`prepare_axis_range_spacing(snapshot, request)` also prepares an isolated fresh
owner from a retained snapshot. Requests/results are detached values in the
Python binding, estimate/result fields are read-only, and processing captures
the complete request and source before releasing the GIL or calling callbacks.
`first_plane_geometry` describes the first **output** plane, while the result
Dataset calibration describes the entire emitted grid.

## C++ API and installed example

Link `imagejxx::core` from an installed SDK and include
`<imagejxx/application.hpp>` or `<imagejxx/execution.hpp>`.

```cpp
imagejxx::AxisRangeSpacingRequest request;
request.orientation.range = {imagejxx::Plane::XZ, 0, 2, 1, 0, 0};
request.physical_vertical_spacing = 1.0;

auto estimate = imagejxx::estimate_axis_range_spacing(source, request);
auto result = imagejxx::reslice_spaced_axis_range(source, request);
auto prepared = application.prepare_axis_range_spacing(request, source_id);
auto published = application.publish(prepared);
```
