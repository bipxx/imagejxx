## Do not copy these other-project remedies blindly

- **CI cancellation:** the inspected `test.yml` has no concurrency group or
  `cancel-in-progress`. QuPath's independent-mode cancellation is not a current
  imagejxx finding. If concurrency controls are later added, key them by actual
  candidate/gate semantics and preserve a final required head; do not add refs
  or a dispatch manager preemptively.
- **Clean-first builds:** no `--clean-first` was found in inspected imagejxx
  scripts/workflow. `ci_native.py` requires fresh disposable CI output by design;
  it is not the local incremental entry point. Keep local caches incremental
  and CI provenance truthful, rather than weakening one to serve the other.
- **Worker count:** other notes recommend three workers plus an integrator.
  Imagejxx's explicit plan remains exactly **three total**, including root/C.
- **Scheduling:** the renderer has intentionally separate processing and
  viewport schedulers. A global-worker-budget lesson does not mandate merging
  them; avoid nested oversubscription while retaining ownership contracts.
- **Python composition:** VisPy's permitted Python geometry composition does
  not authorize a processing fallback here. Imagejxx processing stays C++17;
  Python remains an optional interface/UI launcher.
- **Storage policy:** other projects'20GiB caps or free-space reserves do not
  replace imagejxx's combined8GiB policy. Its retired `build/` stays retired.
- **Unavailable evidence:** reuse does not turn retired G016/Auto proof into
  available evidence or bypass the strict full-family gate.
- **Dependencies and licensing:** a library approved elsewhere is not approved
  here. Review the exact source, transitive code/model/data and obligations.

## Lean execution sequence

1. Select one complete missing user outcome from the existing ready queue.
   Freeze requested/effective profile and the minimum consumed dependencies.
2. Join existing compatible proofs under their original authority; name exact
   missing predicates. Do not repeat a repository-wide audit by default.
3. Finish causal product/driver changes before final capture. A/B may prepare
   one independent successor outside the frozen read set while C integrates.
4. Run installed capability/one-operation smoke, then affected checks. Freeze
   once, consolidate independent review, execute the final required cohort.
5. Run saved-result verification locally to the evidence. Record binary,
   observer, profile and final-head applicability separately. One execution
   can support several criteria when its complete protocol proves them.
6. Retain concise results/failures and necessary lossless captures; verify
   archive members, wait for terminal owning processes/readers and clean only
   explicitly owned eligible paths. Preserve source and protected evidence.
