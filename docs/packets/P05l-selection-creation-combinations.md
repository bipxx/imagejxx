## Outcome and scope

Create a rectangle, ellipse, polygon or freehand **area** on ordinary XY using
Replace, Add, Subtract, Intersect or XOR. Add/Subtract may be selected with
creation-start modifiers; Intersect/XOR have explicit shared ImGui controls.
Preview against the captured active selection, then publish once on successful
completion. Preserve holes, disconnected components and explicit empty masks.
No selection means absence; it must never substitute for an empty Boolean result
because absence can mean whole-plane processing.

This child owns transient active-selection creation. Saved-ROI manager Boolean
operations remain [P05e](P05e-roi-boolean-selection.md). Storing a result is a
separate existing metadata/history edit. Existing edit-ROI move/resize/rotation,
vertex and keyboard modifiers must retain their contracts. Scientific positioned
XY editing, XZ/YZ creation, line/point Boolean conventions, wand combination,
selection brush and full tool/platform/accessibility parity remain required
children. No G013/G015/G016 family is closed here.

Core geometry can operate on any valid native snapshot with admitted XY extent,
without reading image samples. Desktop publication retains existing
`Document::requireLegacyEditable` admission: eager editable T1/C1 documents and
the ordinary canvas. Scientific read-only controls/dispatch must refuse together;
this packet does not relax those guards or add a scientific adapter. RGB/RGBA
samples remain distinct from scientific channels.

## Native command, Python and recording contract

Use one small native selection-creation module; do not add a general validator
or gesture framework. Its public request is an explicit operation and complete
candidate `Selection`. Resolution retains the snapshot, resulting selection and
normalized record. Preparation produces a `DocumentTransaction` against
`Change::Data`, including Pixels/Metadata/Selection and excluding Display.
The caller owns publication; the core never calls a Window or changes workflow.
Freeze exact declarations with root before assigning implementation files.

The entry freeze must also settle these concrete seams before product work:

- Exact admitted candidate kinds and the base-selection policy. Ordinary tool
  creation remains rectangle/ellipse/polygon/freehand area; admitting a mask or
  rotated base does not imply a new creation tool or non-area Boolean behavior.
- A pure native candidate-geometry helper for the observed live Shift/Ctrl
  rules, separate from the already-resolved candidate request. Window supplies
  captured pointer/modifier inputs; Python and C++ callers share the geometry.
  Existing resize math cannot substitute for source-qualified creation math.
- Validation verifies exact stored-result equality against the original
  base/operation/candidate using bounded native composition. Freeze its cost
  and limits before implementation. Replaying against the current selection
  remains forbidden. Validate once per decoded command, rather than serializing
  and validating a full action on each frame.
- Conservative limits for raster scratch, polygon work, retained geometry,
  metadata/record copies and preview/result buffers, with overflow and cancel
  checks before heavy work. Packed-mask bytes alone are not the working set.
  Limits and callbacks cover original-record validation and rebind as well as
  initial resolution; preview performs no pixel reads.

The version1 action has schema `imagejxx.selection-creation-command` and exact
fields `schema`, `version`, `source`, `position`, `operation`, `base`,
`candidate`, `result`. Source contains exact `id`, `pixels_revision`,
`metadata_revision`, `selection_revision`, six TCZYXS `shape` integers, `type`
and `sample_policy`. Position contains captured exact `t`, `c`, `z` indices.
Base is nullable; candidate/result are complete native selection records using
the established nativeV3 geometry/style/attributes/packed-mask representation.
Operation is `replace`, `add`, `subtract`, `intersect` or `xor`.

Record **resolved** geometry; replay does not reconstruct pointer events,
re-read current modifiers or recompute against the current active selection.
Strict replay validates the whole original record and its original result
equation first, then requires the same
owner, Pixels/Metadata revisions, shape/type/policy. Captured selection revision
and base are provenance, not replay admission dependencies: later selection and
display changes are allowed. Publish stored result against a fresh current
snapshot, capturing its actual previous selection. An identical result is a
no-op. This makes replay usable after the original selection change without
silently turning a recorded Subtract into subtraction from a different base.

Explicit full rebind first validates the entire original record, then requires
a new source plus a complete new operation/candidate and resolves against the
new source's current base. It is never automatic on Save/Open or owner mismatch.
Validate exact keys, variant/null rules, integral version/source/indices,
overflow, shape and all selection geometry/attributes before comparing identity;
reject bool-as-int, lossy coercion and malformed original records on rebind.

When recording is on, reserve/check the workflow output before native commit;
append one normalized record only after a changed successful commit. Recording
off, preview, failure, cancel and exact no-op append nothing. Results are
unchanged. Native sessions preserve active/previous selections and action records;
Save/Open retains original recorded source IDs rather than rebinding to loaded
owners. Preserve legacy and unrelated opaque payloads. Test strict new-owner
refusal and explicit rebind separately. No macro-interpreter parity follows.

Python exposes the same typed request/resolution/record and prepared edit through
thin bindings, with no NumPy Boolean implementation. Installed C++ clients use
public headers/core only, with no Python/ImGui/JSON-header dependency. GIL release,
exception/cancel callbacks and captured-object lifetimes must be tested on the
new path, rather than inferred from P05e.
