## Frozen API and serialization

Public module functions:

```python
validate_fixtures(root, documents, inventory=None, *,
                  require_evidence=False, require_complete=False)
fixture_snapshot(fixture, requirements)
contract_fingerprint(contract)
project_cases(format_name, corpus)  # ordered {locator:int,input:JSON,expected:JSON}
```

`fixture_snapshot` selects fixture `id`, `path`, `sha256`, `case_count`,
`reference`, `generator`, `scope`, `comparison`, `requirement_ids`, and the linked
children's `parity_execution.frozen_snapshot` under a `requirements` ID map.
It excludes mutable status/run links. Commercial decisions and remaining work
stay separate obligations. Fingerprints use existing strict canonical JSON,
preserving array order and typed fields, over all contract fields except `sha256`.

The optional `fixtures.json` extension is all-or-none:
`fixture_evidence_schema_version:1`, `fixture_contracts`, `fixture_proofs`.
Absent extensions produce missing-contract gaps for every declared fixture.
Present malformed/Boolean versions, unknown IDs and duplicates reject.

Each contract has:

- `id`, `fixture_id`, `sha256`, `fixture_snapshot`, `format`.
- `case_set`: the complete ordered corpus, each row `{case_id, locator,
  input_sha256, expected_sha256, required_output_paths}`. Locator is the actual
  zero-based index; IDs are unique. Projection hashes cover complete inputs and
  complete expected outputs, independently of the selected match assertions.
- `requirement_scopes`: one row per linked child `{requirement_id, snapshot,
  required:[{case_id,path}], exclusions:[string]}`. Snapshot is that child's
  frozen execution snapshot. Union of required pairs equals the case-set
  selectors; all required pairs remain frozen in the accepted run's contract
  digest. Extra shared-corpus values do not grant a child untested coverage.
- `comparison`: the current fixture's method/atol/rtol plus `numeric_paths`,
  `units`, `rationale`, `nonfinite:"reject"`. Exact has zero tolerance and empty
  numeric paths. Float has nonempty reviewed numeric JSON-pointer selectors,
  finite nonnegative tolerances, units and rationale. Other selected fields are
  exact. Only selectors declared in the required pair set may use tolerance.
- `capture`: the structure below. Missing legacy roles remain explicit gaps.

JSON pointers use RFC 6901 escapes, exact object keys and nonnegative canonical
array indices; reject missing values and duplicate selectors. Whole-file hashes
are raw SHA256; projection hashes are strict canonical typed JSON SHA256. Numeric
comparison accepts finite integral legacy JSON floats without rounding or casts;
bool never equals a number, strings never coerce, containers/dimensions agree.
Float uses the inclusive, reference-relative condition
`abs(observed-reference) <= atol + rtol*abs(reference)`. Nonfinite data and
overflow in comparison arithmetic reject, including values outside tolerance.

Each proof is `{id,contract_id,run_id,trace_id}`. The referenced new immutable run
must declare `fixture_evidence_schema_version:1` and `fixture_traces`, each row
`{id,path,sha256,contract_id,contract_sha256,report_role,report_case_identity,
producer}`. Producer uses the existing nonempty source/artifact identity format
and context. Report/case identity must resolve to an actual passing case in that
run's existing immutable report binding. Existing aggregate reports cannot be
retrofitted with a new trace. A numerical proof certifies no other interface.

The strict JSON trace contains `{schema_version:1,run_id,producer_id,
contract_id,contract_sha256,fixture_id,fixture_sha256,report_role,
report_case_identity,capture_receipt,comparisons}`. `capture_receipt` is the
contract's receipt pin. Comparisons contain exactly one `{case_id,input_sha256,
observed}` per case with required outputs, in frozen order. Observed values come
from the producer; recompute every selected comparison against pinned expected
content. No missing/extra/duplicate cases, claimed counts or asserted match flag
can replace observations. Unknown ancillary trace metadata grants no coverage.

## Capture and adapter contracts

Capture fields are `receipt` and `raw_output` file pins, nonempty
`generator_sources` file pins, `reference_archive` file pin,
`reference_members:[{path,sha256}]`, `driver` and `runtime`.
All byte identities use safe workspace-relative `{path,sha256}`. The primary
generator and its local capture-helper imports must be represented, with source
basenames retained; inspect static AST imports/constants without executing them.
For the reviewed script generators, the primary generator's directory is the
absolute module-search root. Bind helpers to the exact module or package path,
including traversed package initializer files; a same-basename pin elsewhere
cannot satisfy an import. Relative imports ascend from the importing package
directory by their declared level and stay within that root. Standard-library
imports require no local source pin only when no local shadow exists. An
unresolved external, dynamic or ambiguous import remains a capture-provenance
gap; absent bytes do not establish that an import is harmless or nonlocal.
The primary generator's pinned bytes must agree with the fixture generator.

For ImageJ formats, driver is `{text_sha256,artifact:{path,sha256}}`. Verify the
embedded `DRIVER` UTF-8 text hash separately from emitted Java bytes; normalize
the emitted UTF-8 text's CRLF only for text equality, while its byte hash remains
exact. Java runtime is `{kind:"java",executables:[pins],classpath:[pins],
classes:[pins],resources:[pins],version:string}` with nonempty executable,
classpath and class lists. Runtime/resource identities describe the executed
capture, not current same-name files. Reference ZIP/archive and complete member
set/hashes must equal the pinned fixture reference; normalize only the exact
`ImageJ-<revision>/` prefix. Corpus source pins, commit, scope and generator agree
with the manifest; outer ROI scope may add shared-corpus limitations.

For `owned_cases_v1` unit data, driver is null and runtime has
`kind:"owned_synthetic"` with nonempty executable/source identities and version;
the reference archive/member bytes are explicitly project-owned test artifacts.
This variant is valid only for the owned corpus adapter, never an ImageJ adapter.
Synthetic fixture evidence demonstrates validator behavior, not ImageJ parity.

Receipt contains `schema_version:1`, `fixture_sha256`, `case_count`,
`exit_code:0`, `reference_errors:0`, and the same generator/reference/driver/runtime/
raw-output identities as the capture declaration. It does not include its own
pin. Raw output is strict UTF-8 JSONL containing the exact ordered captured cases;
reconcile input and expected projections with the corpus, never just line count.
Failed/empty receipts, malformed JSON, nonfinite values and unhandled reference
errors reject. Capture can verify source data while numerical coverage stays zero.

Allowlisted adapters:

| Format | Complete projection and validity |
| --- | --- |
| `imagej_binary_processor_v1` | Input is every case field except `pixels`; expected is `{pixels}`. Validate operation/options, strict booleans, positive 2D shape/product, finite integral UInt8 source/output. |
| `imagej_conversion_processor_v1` | Input is every case field except `pixels`, including dtype/samples/shape/display range/all parameters; expected is `{pixels}`. Validate declared finite types/lengths/ranges without rounding. Preserve corpus exclusion of native Float64/RGBA extensions. |
| `imagej_roi_style_v1` | Color input is operation/input, expected `{rgba}`; setter/width input excludes stroke/fill/width, expected includes all three. Validate nullable RGBA and finite widths; retain 19 color/36 setters/18 width scope. Only the 18 width cases establish width comparisons. |
| `owned_cases_v1` | Corpus `{schema_version:1,cases:[{input,expected,...}]}` with finite typed JSON; preserve complete input/expected objects and locator order. Clearly project-owned synthetic data. |

Legacy adapter selection uses the three reviewed capture-script basenames;
unknown formats are explicit certification gaps. No dynamic import/comparator.
Missing historical bytes are unavailable gaps in partial mode; changed present
bytes always reject. `require_evidence` rejects missing bytes used by declared
proofs. `require_complete` requires nonempty complete fixture enumeration,
all linked contracts/capture/reference/report/artifact identities and every
required comparison, with no unsupported method/format or unavailable gap.
