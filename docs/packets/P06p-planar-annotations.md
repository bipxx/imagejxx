## Implemented native foundation

`PlanarAnnotation` contains native Selection geometry, an explicit plane and
fixed voxel coordinate, optional T/C membership, name and opaque attributes.
In-plane coordinates describe image-cell boundaries: subtract one half to
obtain voxel centers. The fixed coordinate already names a voxel center.
World conversion uses the full affine; inverse conversion rejects off-plane
points. Visibility matches plane/fixed coordinate and optional T/C. Explicit
zero is a real position; absent T/C are wildcards.

The versioned `imagejxx.planar_annotations` metadata extension binds records to
T/C/Z/Y/X extents. It uses the existing strict native selection codec and
lossless session transport. Geometry validates against each plane's width and
height. Existing native ROI-style validation applies. Limits:4096 rows,65536
vertices/row,16MiB logical metadata,1M nodes; no whole-process memory claim.
Records remain separate from legacy XY selections and saved ROI-manager rows.

Store/update/delete prepare metadata transactions bound to pixel/metadata
revisions. Navigation does not retarget explicit coordinates. Exact no-ops
preserve history; Undo/Redo and nativeV3 Save/Open preserve the complete record.
Annotation validation and edits do not acquire image samples.

Regular Z subset remaps XY fixed-Z positions and drops removed ones. XZ/YZ
boundaries map through selected source voxel centers. Packed masks gather
retained Z rows using native MSB-first bits. Other unsupported extent changes
refuse atomically until explicitly mapped or cleared. Rotated boxes becoming
skew frames under anisotropic remapping also refuse; affine conversion remains
required.
