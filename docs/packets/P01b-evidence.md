# P01b: option, accepted-run and settings-consumer links

Status: **active, subdivided** after P01a's accepted preservation, integration
and archive checks. [P01b1](P01b1-links.md) owns identity/run links; independent
[P01b2a](P01b2a-settings-export.md) supplies fresh native definitions for later
P01b2 consumer proof. P01a's partial records are inputs, not certification.

## Outcome and scope

Make requirement evidence links executable checks. Reject orphan or wrongly
assigned children, unknown/stale runs, missing applicable API/UI evidence and
exposed preference records with no consumer. Preserve the separate
implementation, verification and commercial states. This packet validates
option/run/consumer relationships; P01c/d still own fixture contents, commercial
dependency closure, budgets, platforms, artifacts and repository-wide strict
aggregation. Do not remove the strict checker's unconditional fallback here.

The decided split is **P01b1 identity/run links**, then **P01b2 applicable interface
and settings-consumer proof**, using P01b2a's headless definition exporter. Each
gets owned files, synthetic fixtures and a handoff; this workstream closes only
after both validation contracts pass.

## Entry and ownership

Inputs are `docs/parity/commands.json`, the four P01a manifests,
`docs/parity/inventory.json` and P01a's schema helper. Use actual accepted run IDs,
fixture scope and reports. Family requirements/milestones and previous runs are
immutable inputs to this increment. The 99 families remain partial/open.

The implementation worker owns a focused evidence helper, minimal checker hook,
new owned synthetic tests and schema documentation. Root owns acceptance
recording, plan/packet updates and package verification. Coordinate any additive
manifest/snapshot fields with the schema owner. Workers share the checkout,
preserve others' edits and do not race builds/installations or acceptance writes.

## Contracts

- Child milestones must belong to their owning family's assigned milestones, or
  to the explicit added capability. Candidate/reference identity and links must
  remain consistent. Fixture references must resolve without asserting a match
  merely because a file or capture exists.
- Run IDs are unique and resolve to the accepted inventory. Validate actual
  report paths, successful nonempty applicable suites, exact linked reference
  identity/scope and any declared per-option coverage. Reject unknown,
  mismatched, failed or stale evidence. Historical partial runs remain usable
  only for their recorded scope.
- Separate source/entry-point evidence from executed interface evidence. A
  header, test filename, render smoke or suite total alone cannot certify an
  option's C++, Python and shared ImGui behavior. Complete/verified child claims
  require explicit requirement/surface coverage linked to passing reports.
  Partial records can retain honest unverified gaps; they cannot pass a
  complete-child check.
- Applicable interfaces require their declared checks. Inapplicability requires
  a concrete contract reason and cannot hide a required UI/API option.
- Validate settings keys against a source-identified native settings definition
  snapshot. Preserve the difference between core command defaults and captured
  desktop preference defaults. A settings record requires an identified
  consumer and evidence that the consumer uses the value; the preferences
  control itself is insufficient. An exposed setting awaiting its consumer
  remains explicitly incomplete.
- Keep validation usable without launching the GUI. Owned synthetic manifests
  prove both valid relationships and each missing/wrong relationship. New
  fields must be additive and migration must remain lossless/idempotent.

## Verification and handoff

Test orphan children/fixtures/settings, wrong milestone ownership, duplicate or
unknown runs, missing/failed/stale reports, incomplete applicable interfaces,
misused capture/smoke/count evidence, missing settings consumers and malformed
coverage/default declarations. Include an owned complete child that passes this
packet's gates without claiming commercial/platform certification, and partial
real records that remain accepted only as partial.

Run focused evidence/schema/reference tests, plan integrity and Ruff F, then the
installed Python regression for the integrated checker. Inspect diagnostics for
expected strict rejection. Preserve all original candidates/components/family
contracts/runs; refresh changed packaged sources and final archive byte checks.
Use each child's actual report directory in its current handoff; do not create
a competing umbrella verification run or overwrite accepted reports.
