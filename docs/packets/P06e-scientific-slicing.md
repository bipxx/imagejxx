XY=`[X,Y,Z]`, XZ=`[X,Z,Y]`, YZ=`[Y,Z,X]`.

| Result | Required behavior |
| --- | --- |
| One plane | Shape `[1,1,1,source[vertical],source[horizontal],S]`. Each output sample is the exact selected committed input sample, retaining dtype, S and admitted sample policy. |
| Integer range | Shape `[1,1,count,source[vertical],source[horizontal],S]`, `count=1+(last-first)/step` using integer division. Output plane k fixes the source fixed axis to `first+k*step`; XY/XZ/YZ all use this rule. |

## Versioned command, recording and replay

Add a small native command wrapper around the two existing request types, not a
new workflow engine. Frozen public C++ names:

- `AxisExtractionRequest` is a variant of `AxisPlaneExportRequest` and
  `AxisRangeResliceRequest`.
- `ResolvedAxisExtractionCommand` retains one immutable source snapshot and
  normalized request, exposing its versioned `MetadataObject record()`.
- `resolve_axis_extraction_command(source, request)` validates metadata and
  computes the frozen geometry without reading pixels.
- `validate_axis_extraction_command_record(record)` validates standalone record
  structure and internal geometry/options consistency without a source read.
- `axis_extraction_command_from_record(source, record)` performs strict replay;
  `rebind_axis_extraction_command(new_source, record, explicit_request)` is the
  only cross-source/revision rebind path.
- `prepare_axis_extraction(command, control)` delegates to exactly
  `prepare_axis_plane_export` or `prepare_axis_range_reslice`. Application
  publication consumes its normal `PreparedOperation`; no second extractor,
  duplicate reservation path or new scheduler is introduced.

`ResolvedAxisExtractionCommand` exposes `source()`, `request()`, `layout()`,
`operation()` and `record()` as immutable captured values/const references.
`prepare_axis_extraction(command, control={}, execution_max_working_bytes=SIZE_MAX)`
may only tighten the request cap via `min`; zero execution cap refuses before
reads. It never rewrites the captured record. Python exposes defensive-copy
properties `source/request/layout/operation` and method `record()`, the same
five command functions, and `prepare_axis_extraction(command, *, cancellation=None,
progress=None, checkpoint=None, execution_max_working_bytes=SIZE_MAX)`.

Root exposes `AxisExtractionLayout` in `execution.hpp` with fields `shape`,
`calibration`, `geometry`, `source_axes`, `plane_name`, `working_bytes`, matching
the current private layout. Overloads `describe_axis_plane_export` and
`describe_axis_range_reslice` accept either `(Dataset, request)` or
`(DatasetShape, PixelType, SpatialCalibration, request)`. Both metadata-only
forms use the existing checked layout calculations, with no provider, pixel
read/allocation or user callback. Standalone record validation uses the raw
metadata overload rather than manufacturing a fake dataset/provider.

Desktop keeps existing `exportAxisPlane(source, request)` and
`resliceAxisRange(source, request)`. New
`replayAxisExtraction(record, optional<AxisExtractionRequest> rebind_request={},
document_id=0)` returns the newly attached ID; Python
`Editor.replay_axis_extraction(record, *, rebind_request=None, document_id=0)`
returns that integer. Action `replay_axis_extraction` takes exactly `record`,
optional `document_id`, and optional full `rebind_request` object. The rebind
object contains `operation` plus all fields of its request variant below.
Neither absent `record` nor `{}`/Boolean rebind is accepted. Root's private
publication helper consumes the resolved command; strict replay honors recorded
T/C without reapplying new-command current-T/C capture.

Reuse the existing metadata-only layout/plane-geometry calculations for command
derivations and preparation. If a descriptor needs exposing, root owns the
small helper extraction from `export_layout` / `range_reslice_layout` in
`execution.cpp` and its declaration. Do not implement a second axis/calibration
transform in the command wrapper. The native command worker requests that
shared-file change instead of editing another owner's file.

The native/Python record has an exact recognized schema
`"imagejxx.axis-extraction-command"`, integer version `1`, and operation
`"axis_plane_export"` or `"axis_range_reslice"`. The exact field names,
types and canonical enum spellings are frozen as follows. Exact top-level keys
are `schema`, `version`, `operation`, `source`, `request`, `derived`,
`destination`. Object keys below are exact; no extra/missing keys are accepted.

| Object | Exact fields / representation |
| --- | --- |
| `source` | `document_id` positive uint64; `shape` six positive native-int TCZYXS values; `pixel_type` one of `uint8/uint16/float32/float64`; `sample_policy` `finite_only` or `preserve_quiet_nan_float32`; `revisions`; `calibration`. Quiet-NaN policy requires Float32/S1. |

Equivalent exact signed/unsigned integer representations may decode, while

## Preview, failures, resources and publication

An accepted export always reads the captured **committed** native dataset.
An installed Gaussian preview is presentation state; never export its staged
pixels, implicitly Apply it, retarget it or serialize it into the output.

READY preview is not Apply busy. Opening/editing/canceling the slicing form and
deterministic malformed/inactive/stale refusals preserve its job/generation,
retained preview, target and reservation. A valid preparation may coexist with
that retained preview. A preparation/admission failure preserves both owners and
membership; it does not need a new Gaussian preflight/reservation API.

Only successful output publication/activation triggers the existing source-tab
Gaussian invalidation/cancellation policy. Observe eventual lane/reservation
release through bounded event hooks. The source is unchanged. Gaussian queued,
running or READY Apply, threshold Apply and legacy edits remain busy and reject
slicing before output preparation. Explicit source-tab changes/close retain
their established P06d1 cancellation behavior.

Keep the existing atomic order: validate metadata/caps, prepare the native fresh
candidate, stage the exact facade/Pane/tab capacity and diagnostics, then native
publish, then no-throw attachment. Any throwing frontend work precedes adoption;
failed preparation, frontend admission, stale publication or source close leaves
no orphan native owner, adapter, Pane, output tab, result or workflow entry.
Publication observers record actual values and never supply expected pixels or
throw after adoption.

Reuse native checked working-byte calculations and the smaller nonzero
`processing_memory_mb` cap. Declare source, output/fallback/strip, renderer,
session/report and retained-preview headroom separately: the existing processing
reservation setting is not a total-process memory guarantee. No virtual desktop
admission, full-TCZ materialization or new generic source cache is authorized.
Keep established texture/dimension constraints; metadata overflow and configured
caps reject before samples are read, and execution failures publish nothing.

Unsupported states retain atomic refusal: lazy/non-eager desktop owners,
scientific Fourier state, S2 and any source/display property outside the current
desktop admission contract; invalid enums/types/booleans-as-indices, negative or
past-end indices, zero/negative Step, reversed ranges, foreign/inactive/closed
scientific owners and stale Pixels+Metadata captures. Preserve opted quiet-NaN
Float32/S1 **exact** extraction, signed zero and payload transport; this adds no
interpolating/nonfinite processing support. Unsupported scientific orientation,
physical-grid, Slicer-bilinear and generic legacy `reslice` routes stay guarded.
